>[!note] ターミナルとは
>キーボードとディスプレイでデータを入力・出力する末端装置。[](https://e-words.jp/w/%E7%AB%AF%E6%9C%AB.html)​  
>CLIを提供するソフトウェア。テキストコマンドでシステム操作。[](https://www.cc.kyoto-su.ac.jp/~yasuda/proga/02/Command1.html)​  
>ファイル管理、プログラミングに効率的。

## OSごとのメイン
### Windows
Windows Terminal（デフォルト）。PowerShellまたはコマンドプロンプト。
### macOS
Terminal.app（標準）。zsh（Catalina以降デフォルト）またはbash。​
### Linux
GNOME Terminal、Konsoleなどディストリビューション依存[^1]。bashまたはzsh。

> [!note] bashとかzshとか何なのか
> - ターミナルは、パソコンで黒い画面に白い文字が出てコマンドを打つ「窓」のこと。キーボードで文字を入れて、結果を見る道具。[[choge-blog](https://www.choge-blog.com/%E3%83%A9%E3%82%A4%E3%83%95%E3%83%8F%E3%83%83%E3%82%AF/windows11terminanldefaultcommandprompt/)]​  
>  - zshやbashは、その窓の中で動く「頭脳」。君が打ったコマンドを理解して、パソコンに動かさせる賢いお助けマン。[[choge-blog](https://www.choge-blog.com/other/bashvszsh/)]​  
>  - ターミナルが窓で、zsh/bashが中身のプログラム。

[^1]: ディストリビューション依存とは、Linuxの種類（Ubuntu、Fedoraなど）によって標準のターミナルが違うこと。[](https://tanoike.com/linux-package-dependencies-explained)​  UbuntuならGNOME Terminal、KDEならKonsoleがよく使われる。各ディストロがデスクトップ環境を選ぶから。「依存」とは、ディストロごとに変わるという意味

## macOSとLinuxが似ている理由
どちらもUnix由来のOSだからターミナルが似てる。[](https://zenn.dev/k_log24/articles/582af625164d41)​  
歴史的に同じルーツ（Unix）を持ち、コマンドやシェル（bash/zsh）が共通で使える。​  
だからWindowsと違って、黒い画面で同じような操作ができる

## shの意味
- シェル（shell）「殻」の意味。  
- コマンドを包んでOSに伝える「外側の殻」だから、bash（Bourne Again SHell）、zsh（Z SHell）と「sh」がつく 
- 昔のBourne Shell（sh）が元祖で、後継たちが名前を引き継いだ。

## npmとかyarnとか
- npm、yarnはJavaScriptの「パッケージマネージャー」。  
- Node.jsのプログラムに必要な部品（ライブラリ）をダウンロード・管理する道具
- npmが元祖、yarnはnpmの高速版として登場。他にpnpm、bunもあって、インストール速度や容量効率で使い分け

## Windowsは昔はDOS由来でツール互換性貧弱だった
- MacやLinuxはUnixベースでターミナルやコマンドがプログラミング向き
- 一方、WindowsはDOS由来でツール互換性が悪く貧弱と言われてた
- 今はWSL2[^2]のおかげでWindowsもLinux環境を簡単に動かせるから、だいぶ追いついた

[^2]: Windows上でLinux環境を軽量仮想マシンで動かす仕組み。[](https://note.com/genelab_999/n/nc3b427d9dd39)​  UbuntuなどのLinuxディストリビューションをインストールでき、ターミナルでLinuxコマンドをそのまま使える。[](https://learn.microsoft.com/ja-jp/windows/wsl/about)​  プログラマーがWindowsでLinuxツール（Dockerなど）を楽に扱えるようになり、開発環境の弱点を解消した
## Dockerとは
- アプリとその必要な環境を「コンテナ」という軽量パッケージにまとめて動かす技術
- 仮想マシンより速く、どこでも同じ環境で動くから、開発・運用で大人気
- WSL2でWindowsでも簡単に使えるようになった

## Dockerの「環境」とは
 - アプリを動かすために必要なOS、ライブラリ（Node.jsのnpmパッケージなど）、設定ファイル、依存関係の全部を指す
 - nodeやexpressみたいなライブラリを指定・インストールした状態をコンテナにパックできる。package.jsonがそのリスト役。
 - Dockerfileで「Node.js入れてnpm installして…」みたいに書けば、manifest.js的な役割で誰でも同じ環境再現可能

## Webpack ? Vite ?
**Webpack**: JS/CSS/画像などを1つのファイルにまとめ、ブラウザで読み込める形にする「バンドラー」。設定複雑で大規模プロジェクト向け。

**Vite**: 新しい高速バンドラー。開発中はブラウザのネイティブ機能を使い超速、設定も簡単。小～中規模プロジェクトの標準。​

**今どき**: Viteが主流。`npm create vite@latest` で即開始可能。

## バンドラーとは
複数のJS/CSS/画像ファイルを1つのファイルにまとめ、ブラウザが効率的に読み込める形に変換するツールでフロントエンド開発専用。​

**ZIPとの違い**
- ZIP: 単純圧縮（展開が必要）
- バンドラー: 依存関係解析→コード変換（TypeScript→JS）→ツリーシェイク（不要コード除去）→1ファイル生成。​

## **`npm run build`の仕組み**

`npm run`は**package.jsonの`scripts`セクションに書かれたコマンドを実行するだけ**。

```  json

`{   "scripts": {    "build": "esbuild main.ts --bundle --outfile=main.js"  } }`
```

- `npm run build` → `esbuild main.ts --bundle --outfile=main.js`を実行    
- `build`はnpmの関数じゃなく、**開発者が決めたタスク名**
- Obsidianプラグインではesbuild（バンドラー）がTypeScriptをJSに変換している

**流れ**: package.jsonでタスク登録 → `npm run タスク名`で実行 → バンドラーなどが動く

## バンドラー？
**esbuild**はWebpack・Viteと同列の**超高速バンドラー**。Go言語製でTypeScript→JS変換も爆速。
- **Webpack**: 設定豊富、大規模向け
- **Vite**: 開発サーバー特化（内部でesbuild使用）
- **esbuild**: 純粋な高速コンパイラ/バンドラー
Obsidianの`npm run build`で使われてた**esbuild**は、**最新最速のバンドラー**なんだ。


Obsidianプラグインは **`main.js` + `manifest.json` + `styles.css`**  の3点セットさえあれば動く（どんなバンドラー使ってもOK）
 - 公式テンプレートの`package.json`に`"build": "esbuild ..."`と書いてあるから、`npm run build`すると**esbuild**が動くだけ
- `scripts`の`"build"`を`"webpack ..."`とか`"vite build"`に書き換えれば、好きなバンドラーでOK

> [!note] ビルド > バンドラ
> - **ビルド** = 大きな概念。「開発コード → 配布・実行可能な形」に変換する全工程  
（TypeScript→JS、minify、画像圧縮、環境変数差し替えなど）
> - **バンドル** = ビルドの中の**1つの機能**。複数ファイルを1つにまとめる処理。

## 最近のシェルのトレンド in 2026
**主流シェル**
- **zsh**: macOS Catalina以降のデフォルト。Oh My Zshで補完・テーマが充実 
- **bash**: Linux標準。POSIX準拠でどこでも動く
- **fish**: 初心者向け。美麗プロンプト・出荷時補完が強み

**注目新顔**  
**nushell (nu)**: 構造化データ（JSON/テーブル）をネイティブ処理。`ls | where size > 1mb`みたいにSQL風でファイル操作可能

**モダン機能**
- **Mosh**: 切断耐性SSH（途中切れても続きから）    
- **tmux**: ターミナルマルチプレクサ。リモート作業の必需品
- **Direnv**: .envrcでディレクトリごとに環境変数自動設定

## npm以外のパッケージマネージャー
## npm・yarn・pnpm比較

| 項目 | npm | yarn | pnpm |
|------|-----|------|------|
| **登場** | Node.js標準（2009） | npm高速版（2016） | ディスク効率特化（2016） |
| **速度** | ○（改善中） | ◎（並列＋キャッシュ） | ◎◎（最速） |
| **容量** | △（全コピー） | △（全コピー） | ◎（ハードリンク） |
| **ロック** | `package-lock.json` | `yarn.lock` | `pnpm-lock.yaml` |
| **コマンド** | `npm i express` | `yarn add express` | `pnpm add express` |
| **おすすめ** | 初心者・小規模 | チーム開発 | 大規模・モノレポ |

**結論**: 小さめならnpm、中規模ならyarn、大規模ならpnpmが鉄板！

## nodeとは？
- **Node.js**とは、JavaScriptをブラウザ外（サーバーやPC上）で動かせる実行環境。
- Vue開発で`npm run dev`とか叩いてたのは、**Node.js上で動く開発サーバー**だったよ。npmの「n」はまさに**Nodeのn**。
今までのnpm/yarn/pnpm/Vite話は全部**Node.js**前提の世界！

## javascriptとは？

JavaScriptは1995年、Netscape Navigatorブラウザ内で動的なページ操作（ボタンクリック時の反応など）を実現するため、Brendan Eich氏がわずか10日で開発した。​

当初はブラウザ専用で、サーバーサイドやデスクトップ単体での実行は不可能。「Mocha」→「LiveScript」→「JavaScript」と名前が変わり、Java風のシンタックスで普及した。​

==2009年にNode.jsが登場==し、GoogleのV8エンジンを利用してサーバーサイド実行が可能に。これがきっかけでnpmエコシステムが爆発的に拡大し、今やフロント・バックエンド両方で標準言語となった。​

## node.jsはWEB開発をどう変えたか
**Node.js登場前（～2009年）のWeb開発**
 - 静的HTML/CSS + サーバーサイド言語（PHP、Perl、ASP）の時代。
 - ページ遷移ごとにサーバーにリクエストを送り、全ページ再読み込み
 - JavaScriptは最小限で、Javaアプレットが注目された。​

**フロント**: HTML（静的）+JavaScript（簡単なバリデーションのみ）  
**バック**: CGI（Perl）→PHP→Java Servlet→Ruby on Rails（2004年頃）で動的ページ生成

**Ajax登場（2004年）** で部分更新が可能になり、Gmailのようなスムーズな操作が生まれたが、まだサーバーサイド中心だったよ

> [!summary] わかりやすく
> **昔のWebページ**  
> 本をめくるみたいに、クリックするたびページ全体が白くなって読み込み直し。全部リロードで遅かったよ。
> **Ajaxで変わったこと**  
> お菓子袋から1つだけ取り出すように、ページの一部だけサーバーからデータを持ってきて更新。Gmailみたいにサクサク動くようになった。
> **Node.jsでさらに**  
> JavaScriptがサーバーでも動くようになり、フロントとバックエンドが同じ言語で開発可能に。お店のお客さん（ブラウザ）と厨房（サーバー）が同じ言葉で話せるようになったんだ！​


**前**: お客さん側（ブラウザ）はJavaScript、厨房側（サーバー）はPHPやJava
→ **言語が違うから2人開発チーム必要**

**Node.js後**: お客さんも厨房も**JavaScript**
→ **1人で両方書ける！**

同じ言語で統一できるから、コード共有しやすく、開発スピードが爆上がり。**フルスタックJS[^3]** 時代到来だよ！

[^3]: **フルスタック**とは、Webアプリの**フロントエンド（画面）からバックエンド（サーバー・データベース）まで全部作れるエンジニア**のこと。​Node.js登場前はフロント専門・バック専門の2人必要だったけど、同じJavaScriptで両方書けるようになったから**1人で完結**可能に。**開発速度2倍、コスト半減**の革命だったよ！
