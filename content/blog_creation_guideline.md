# ブログ記事作成ワークフロー

このドキュメントは、私（AI）がブログ記事を作成する際の標準的なワークフローを定義するものである。

## 1. トピック提案フェーズ

ユーザーから「ブログ記事を書いて」というような曖昧な指示があった場合、以下の手順でトピックを5つ提案する。

1.  **コンテキスト分析:**
    *   `x/blog/` ディレクトリ内の既存ブログ記事をリストアップし、特に直近の記事のテーマ、文体、キーワードを分析する。
    *   `ATLAS/00_inbox/` ディレクトリ内のノートをすべて読み込み、ブログのネタとなりうる候補を洗い出す。

2.  **候補の選定:**
    *   `00_inbox`内の各ノートについて、以下の基準で評価する。
        *   **独自性:** 筆者ならではの視点、洞察、ユニークな仮説が含まれているか。
        *   **関連性:** 他のノートへのリンク（`[[...]]`）や、他のノートからのバックリンクが豊富にあるか。`search_file_content` を活用してノート間の繋がりを調査する。
    *   既存ブログの文脈と関連しつつ、新鮮な視点を提供できるトピックを優先する。

3.  **提案:**
    *   選定した候補の中から、最も魅力的と思われるトピックを5つに絞り込む。
    *   各トピックについて、なぜそれが面白いのか（独自性、関連性など）を簡潔な説明と共にユーザーに提示する。

## 2. 執筆フェーズ

ユーザーが提案の中からトピックを一つ選択したら、以下の手順で記事を執筆する。

1.  **深掘り調査:**
    *   選択されたトピックに関連するすべてのノート（`00_inbox`内外を問わず）を `read_many_files` や `search_file_content` を使って収集し、内容を精読する。

2.  **構成案作成:**
    *   収集した情報に基づき、以下の要素を含む記事の構成案を（内部的に）作成する。
        *   **タイトル:** 読者の興味を引く、魅力的で具体的なタイトル。
        *   **導入:** 読者の共感を呼ぶ問いかけや、意外な事実の提示。
        *   **本文:** 複数のセクションに分け、ストーリー性のある展開を心がける。
        *   **結論:** 記事全体の要約と、読者へのメッセージ。

3.  **執筆:**
    *   以下の執筆スタイルを厳守する。
        *   **文体:** 読者に直接語りかけるような、会話的で親しみやすいトーン（note.com風）。「〜です・ます」調を基本としつつ、「〜でした」「〜でしょう」などを織り交ぜ、自然な語り口にする。
        *   **構成:** 一文を短くし、1〜2文ごとに改行を入れる。
        *   **書式:** 強調は `**`、引用は `>` を使用する。
    *   記事のメタデータ（`title`, `date`, `description`, `tags`, `slug`）をYAMLフロントマターとして記述する。

4.  **納品:**
    *   完成した記事を `x/blog/` ディレクトリに保存する。
    *   ファイル名は `YYYY-MM-DD_トピックを要約したスラグ.md` の形式とする。
