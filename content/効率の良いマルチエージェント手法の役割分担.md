# 効率の良いマルチエージェント手法の役割分担
いい着眼点です。この手の設計は「役割を増やしすぎて調整コストが爆発する」か「まとめすぎて責任が曖昧になる」かのどちらかに転びがちなので、順番に整理します。

## 1. 役割分割は「タスク」ではなく「判断の種類」で切る

タスク単位（章ごと、シーンごと）で役割を作ると人数（エージェント数）が無限に増えます。そうではなく、**判断の性質が違うところだけ**で切るのが最小構成の考え方です。

最小構成の目安：

|役割|担う判断|入力|出力|
|---|---|---|---|
|**構成（Architect）**|何が起きるか、順序、伏線配置|設定資料、テーマ|プロット/章立て|
|**執筆（Writer）**|プロットを文章化する際の表現判断|確定プロット、設定資料|原稿（ドラフト）|
|**校閲（Reviewer）**|整合性・品質・文体のブレ|原稿、設定資料|指摘リスト|

この3つで十分に回ることが多いです。「設定管理」を独立エージェントにしたくなりますが、これは**役割ではなくデータ**として扱うのがコツです。つまり「設定シート」というノート（後述）を全エージェントが参照・追記する共有リソースにし、専任エージェントを置かない。役割を増やすと「誰がこの矛盾に責任を持つか」が逆に曖昧になります。

判断に迷ったら「この作業、Writerが片手間にやっても質が落ちないか？」と自問し、落ちないなら別役割にしない、というのが実務的な基準です。

## 2. Obsidianでの整理：人間もAIも同じ入口から読める構造にする

```
/00_設定/         ← Canon（動かない事実）
  人物.md
  世界観.md
  用語集.md
/01_プロット/
  全体構成.md      ← MOC（マップ・オブ・コンテンツ）
  ch01_plot.md
  ch02_plot.md
/02_原稿/
  ch01_draft.md
  ch02_draft.md
/03_レビュー/
  ch01_review.md
/_ダッシュボード.md ← Dataviewで全体状況を集約
```

ポイントは3つです。

- **YAML frontmatterを構造化データとして使う**（人間には見出し情報、AIには機械可読なメタ情報として機能）

```yaml
---
type: chapter
number: 1
status: draft_review_pending
role_next: reviewer
depends_on: [ch01_plot]
---
```

- **命名規則を固定**して、AIが「このプロットに対応する原稿はどれか」を迷わず特定できるようにする（`chXX_plot` → `chXX_draft` → `chXX_review`）。
- **テンプレート化**（Templaterプラグイン）して、新しい章ノートは常に同じ構造で生成する。構造が毎回違うと、AIエージェントへのプロンプトも毎回作り直しになります。

## 3. チェックボックスは「状態遷移」として設計する

漏れをなくす本質は、チェックボックスの羅列ではなく**次の役割が動き出す条件を明示すること**です。

```markdown
## ch01 パイプライン
- [x] プロット確定（Architect）
- [x] 初稿執筆（Writer）
- [ ] 校閲済み（Reviewer）
- [ ] 設定整合性チェック済み
- [ ] 確定
```

これをただの記録にせず、**「前のボックスが埋まっていなければ次の役割は着手しない」という明文ルール**をプロンプト側にも書いておく（例：「`校閲済み`が未チェックの章は執筆対象にしない」）。これで人間が見ても抜けが一目瞭然になり、AIも自分の担当が来たかどうかをノートを読むだけで判断できます。

さらに、Dataviewで全ノートのチェックボックス状態を横断集約したダッシュボードを1枚作ると、「どの章が今どこで止まっているか」が全体俯瞰できて、抜け漏れの発見コストがゼロに近づきます。

```dataview
TABLE status, role_next
FROM "02_原稿"
WHERE status != "確定"
```

## 4. 役割間の「受け渡し仕様」を明文化する

見落とされがちですが、これが一番効きます。各役割の出力フォーマットを短い契約書のように書いておく。

```markdown
## Writerの完了条件（Definition of Done）
- 原稿は確定プロットの箇条書きを全て反映している
- 新規固有名詞は00_設定に追記済み
- 文体ガイドの一人称/三人称ルールに従っている
```

これがないと「校閲役が何を基準に指摘すればいいか分からない」という曖昧さが残り、結局人間が毎回口頭で補足することになります。
